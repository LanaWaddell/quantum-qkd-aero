## 0. Scope

ADAPT-1 implements ADR-0004 D1's monitoring/attribution function as a passive, separately-simulable monitor: synthetic scalar channel-state traces + a committed environmental reference → TWIN-1 calibrated diagnostics → `AttributionVerdict` under rules frozen in the reference before observation → `DegradationAttributionEvidence` with canonical digests. It also discharges D1's enumeration duty (observable registry with latency/trust/applicability annotations).

Out of scope: active probing/watermark attribution (ADAPT-2, where `ADVERSARIAL_SUSPECTED` earns its evidence basis); policy decisions (HYBRID Stage 2); live-pipeline coupling; multidimensional hidden-state or multivariate-observation references (deferred with the multivariate work); any change to `contracts.py` vocabulary, `hybrid/states.py`/`registry.py` semantics, physics modules, or `qkd.fixtures` (separate lane; never imported here). Nothing here reads key material, controls anything, or claims to prove attack presence or absence.

## 1. Honesty core (binding)

- **The passive monitor never emits `ADVERSARIAL_SUSPECTED`** (D-A1-2, Echo-confirmed twice). Verdict range: `ENVIRONMENT_CONSISTENT`, `UNEXPLAINED`, `INSUFFICIENT_EVIDENCE` (`NOT_APPLICABLE` reserved for non-monitorable observables at the registry boundary, which reject before evaluation). Passive diagnostics establish inconsistency with the committed reference; adversary attribution requires ADAPT-2's watermark evidence. A named test asserts the emitted set exactly.
- **Statistical honesty (A1 — supersedes v1.2's error):** TWIN-1 calibrates whiteness and NIS **separately at their own α = 0.05 each and explicitly makes no aggregate false-positive-rate claim and defines no aggregate verdict** (`twin.py` module contract, verified verbatim). ADAPT-1 therefore: (i) reports both component results and their reason codes separately in the evidence; (ii) maps *either component rejection* to the single required verdict `UNEXPLAINED` as an **explicitly labeled ADAPT operational OR-mapping over separately calibrated component results — never a TWIN-1 aggregate statistical verdict**; (iii) freezes the conservative familywise bound `ADAPT_FAMILY_ALPHA_BOUND = min(1.0, 2·α) = 0.10` by the union bound, with no TWIN-1 calibration change; (iv) `confidence = 1 − ADAPT_FAMILY_ALPHA_BOUND = 0.90` for conclusive verdicts, defined in the docstring as a **conservative procedure-level calibration label only** — never the probability that the verdict, cause, reference, or source is correct; `0.0` for `INSUFFICIENT_EVIDENCE`; (v) ensemble tests check each component's null rate against TWIN-1's existing exact-binomial bands, and the combined `UNEXPLAINED` null rate against a **one-sided bound valid for p ≤ 2α** — never an exact band centered at α.
- A matched-law degradation trace yields `ENVIRONMENT_CONSISTENT` — correctly, per the TWIN-1 theorem — and the test suite pins this as the Stage-2 downgrade-attack input, intended behaviour, not defect. `ENVIRONMENT_CONSISTENT` means compatibility with the committed reference; never authenticity, absence of attack, or security.

## 4. Monitor (`adaptive/monitor.py`) — A3 complete production contract

`AttributionMonitor.evaluate(trace, reference, *, evidence_id, produced_at_utc) -> DegradationAttributionEvidence` — pure function; caller supplies identity and clock; deterministic and replayable.

- **Two disjoint input classes (R4), with the C2 exact-length trichotomy:** *contract violations* — nonfinite samples, malformed timestamps, unknown/non-`monitorable` observable, observable mismatch with the reference, invalid calibration keys, `committed_at_utc ≥ window_start_utc`, `produced_at_utc < window_end_utc`, schema/canonical violations, **and `len(values) > calibration.effective_n`** (named `TraceLengthContractError`; no implicit truncation or window selection, ever — the monitor never chooses which samples count) — raise named errors and **never produce an evidence object**. *Evidence-quality shortfalls* — a structurally valid trace with `len(values) < calibration.effective_n` — yield `INSUFFICIENT_EVIDENCE` with the single short-window code `window_below_effective_n`. `len(values) == calibration.effective_n` → evaluate. All three branches pinned by named tests.
- Diagnostics: TWIN-1 filter (`f,h,q,r,x0,p0`) + calibrated whiteness and NIS; both component outcomes recorded separately; verdict per the §1 operational mapping.
- **Evidence field production (A3, frozen):** `evidence_id` — caller-supplied, non-empty (uniqueness is the caller's contract); `produced_at_utc` — caller-supplied, canonical grammar, `≥ window_end_utc`; `source_integrity` — closed vocabulary, v1: **`"not_cryptographically_verified"`** (C3: an integrity *assessment*, literally stating the §1 rule — v1.3's `"declared_synthetic"` was provenance, not integrity; provenance stays on the trace as `provenance = "synthetic"`); `source_independence` — closed vocabulary, v1: `"channel_derived_not_independent"` (ADR contract: adversarially shapeable; no causal independence implied); `freshness` — exactly `"fresh"` iff `produced_at_utc − window_end_utc ≤ max_freshness_age_s` (equality fresh), else `"stale"`, computed from the digested rule; `reason_codes` — closed vocabulary in frozen order **(`whiteness_pass`, `whiteness_reject`, `nis_pass`, `nis_reject_high`, `nis_reject_low`, `window_below_effective_n`)** with the C3 emission rule: **every conclusive verdict emits exactly one whiteness outcome code and exactly one NIS outcome code, in that fixed order** — `ENVIRONMENT_CONSISTENT` ⇒ `(whiteness_pass, nis_pass)`; `UNEXPLAINED` ⇒ the realized pass/reject pair — so both component outcomes are explicit in the frozen evidence object and "passed" is never conflated with "not recorded"; `INSUFFICIENT_EVIDENCE` emits only `window_below_effective_n` and **no** diagnostic outcome codes, because the diagnostics did not run. Raw statistics and thresholds are **not** fields of this frozen evidence contract — ADAPT-1 records component outcomes, not the diagnostic report; `evidence_refs` — exactly `(trace_id, reference_id)` in that order; `reference_digest` — the reference's computed digest; `monitor_id`/`monitor_version` — declared constants; `confidence` per §1(iv). Construction tests cover every branch.
