## 0. Scope statement

LINK-6a consumed the four detector-side deferred observables through the QKD receiver model. LINK-6b consumes the **three remaining channel-side deferred observables** — `timing_jitter_s`, `frequency_offset_hz`, `misalignment_error` — through the **same receiver path**, as three estimator-owned mappings, and adds the built-in constant-parameter owners those observables lacked. After LINK-6b, the residual bridge (`apply_link_state`) rejects exactly one non-identity field: the source partition's `intensity_factor` (LINK-5 gate items 1–2, still deferred by its epistemic contract). `bb84.py` and `link.py` remain untouched. Out of scope: source consumption; receiver-aware Eve; finite-key; timing-recovery/synchronisation error (mean arrival offset); Doppler *tracking dynamics* (a residual fraction is declared, not a tracker); spectral coupling between the filter and the background rate (declared limitation, §6); adjacent-gate leakage beyond the declared guard; geometry-coupled polarization-frame rotation (a follow-up needing an orbit frame convention; recorded, not invented). All emitted rates remain **asymptotic, model-conditional**. The default path — `receiver=None` — remains byte-identical; all frozen-hash tests unmodified.

## 1. The three consumption mappings (estimator-owned, receiver path)

All three enter the LINK-6a receiver chain **before** the base-statistics call (`run_decoy_bb84` on the detector copy) as **channel-copy folds** — the two acceptance factors multiply the channel transmittance, the misalignment mapping replaces `intrinsic_qber` — so both certified base laws (`Q_x = 1−(1−y0)e^{−ημ}`, `T_x = ½y0 + e_d(1−e^{−ημ})`) are inherited unchanged; nothing else in the §1.3/§1.5 afterpulse–availability chain or the §5 PDT chain changes. The order is fixed and tested: gate acceptance and filter acceptance are **signal-only** multipliers of the optical transmittance — they never touch `p_bg`/`p_dk`/`p_noise`/`y0` (noise per gate is already gate-and-filter-referred by the LINK-6a ownership contract) and therefore leave the **base** vacuum gain `Q_vacuum = p_noise` unchanged. **They do change the post-afterpulse `Q'_vacuum` whenever `p_ap > 0`** (B1 — a v1.1 error): LINK-6a's shared detector history makes `a = p_ap·Q̄_reg` depend on the aggregate occupancy `Q̄ = Σπ_x Q_x`, so lower signal/decoy gains ⇒ lower `a` ⇒ lower `Q'_vacuum = 1−(1−Q_vacuum)(1−a)` (Echo's live-code check: `Q'_vacuum` 5.43e-4 at η = 0.10 vs 2.74e-4 at η = 0.05, `Q_vacuum = 1e-6`, `p_ap = 0.02`). That cross-intensity coupling is the intended physics, and §8 tests it as such rather than asserting a false invariant. The multipliers are `f`-independent, so in PDT mode they are applied once to `η_base` before the node loop.

### 1.1 `timing_jitter_s` → gate acceptance (the LINK-6a "feasibility coupling" made concrete)

`timing_jitter_s` is the stack-composed **rms** arrival-time spread `σ_t` (quadrature composition of independent contributors is LINK-1's discharged rule; a declared-correlated contributor still raises there — unchanged). Declared model: signal photon arrival time relative to the gate centre is Gaussian, `τ ~ N(0, σ_t²)`, with **perfect timing recovery** (mean offset zero — the mean-offset field is future work, §6). Acceptance is the mass inside the gate of width `Δt = gate_window_s`:

```
η_gate = erf( Δt / (2·√2·σ_t) )          (η_gate ≡ 1 exactly when σ_t = 0 — parity anchor)
```

`Δt` is the LINK-6a `gate_window_s` control (same identity, same bounds `[MIN_GATE_WINDOW_S, 1/f_rep]`); it becomes **required-when-consumed** for `timing_jitter_s` too (§2). **Adjacent-gate leakage guard (binding):** photons landing in a neighbouring gate would register there as signal-correlated noise; this is neglected under the declared guard `P(|τ| > 1/f_rep − Δt/2) ≤ JITTER_LEAK_TOLERANCE = 1e-9` (two-sided Gaussian tail via `erfc`), else named error `GateLeakageGuardError` — same shape as the PDT tail rule: declared, tested, never silently accepted. Under live defaults (`1/f_rep = 10 ns`, `Δt = 1 ns`, `σ_t = 100 ps`) the leaked mass is far below the tolerance.

### 1.2 `frequency_offset_hz` → spectral-filter acceptance (Doppler consumption)

`frequency_offset_hz` is the composed carrier offset (LINK-3 `DopplerShiftEffect`: `−(v_r/c)·ν_carrier`; ~±8 GHz peak for the default pass at 1550 nm). Declared receiver model: a **Gaussian spectral filter** of rms passband `σ_f` and unit peak transmission (insertion loss belongs to `system_efficiency`), a **Gaussian source line** of rms width `σ_s`, and a **declared residual Doppler fraction** `r ∈ [0, 1]` (perfect tracking `r = 0` … uncompensated `r = 1`; the tracker itself is not modelled — `r` is the declared residual after whatever compensation the system has). Acceptance:

```
Δν_res   = r · frequency_offset_hz
η_filter = σ_f / √(σ_f² + σ_s²) · exp( − Δν_res² / (2·(σ_f² + σ_s²)) )
           (η_filter ≡ 1 exactly when Δν_res = 0 and σ_s = 0 — parity anchor;
            the prefactor is the finite-linewidth loss at zero offset)
```

`σ_f = filter_sigma_hz` and `r = doppler_residual_fraction` are **two new declared controls** (§2). `σ_s = source_linewidth_sigma_hz` is a **`ReceiverModel` model parameter** (default `0.0`; validated **finite and ≥ 0** at construction, in the v2 manifest schema, and by negative NaN/±inf/negative tests — a source property the receiver *assumes*, recorded in the manifest; a future source-partition owner may supersede it). Uncompensated Doppler through a 1 GHz filter is fatal (`η_filter ≈ 1e-14` at 8 GHz) — that is physics, and it is why the residual fraction is a required declaration, not a default.

**Activation rule (B2, frozen):** (i) `filter_sigma_hz` is **required** when `frequency_offset_hz ≠ 0` **or** `source_linewidth_sigma_hz > 0` (the finite-linewidth prefactor is undefined without a filter — a nonzero recorded receiver parameter is never silently ignored); (ii) `doppler_residual_fraction` is required only when `frequency_offset_hz ≠ 0`; (iii) if `frequency_offset_hz = 0` and `σ_s = 0` and no filter is supplied, `η_filter = 1.0` **exactly** (short-circuit, parity anchor); (iv) if a filter is supplied with `frequency_offset_hz = 0`, the finite-linewidth acceptance `σ_f/√(σ_f²+σ_s²)` is still computed (and equals 1.0 exactly when `σ_s = 0`); (v) `doppler_residual_fraction` supplied while `frequency_offset_hz = 0` is accepted-but-unused and recorded (LINK-6a rule). Each branch is a named test.

### 1.3 `misalignment_error` → intrinsic error probability

`misalignment_error` is the single composed misalignment **error probability** (unit-interval field; LINK-1 permits at most one nonzero contributor at the stack — unchanged, still raises on two). Estimator-owned mapping: independent-flip composition with the channel's `intrinsic_qber = e_d`:

```
e_d' = e_d + m − 2·e_d·m          (XOR of two independent error probabilities;
                                   e_d' ≡ e_d exactly when m = 0 — parity anchor)
```

applied as `replace(channel, intrinsic_qber=e_d')` before the base call, so `T_x = ½y0 + e_d'(1−e^{−ημ})` is inherited from `bb84.py`. `bb84.py`'s existing domain check `0 ≤ intrinsic_qber ≤ 0.5` continues to apply to `e_d'` (m ≤ ½ ⇒ e_d' ≤ ½ for e_d ≤ ½, tested). The evidence memo's `sin²(Δφ)` **time-bin phase model** is discharged as an *owner* mapping (§4, `PhaseMisalignmentEffect`), not as a stack combiner — exactly the LINK-1 boundary.

### 2.1 Reconciliation with ADR-0003 §3.6 (B7)

ADR-0003 §3.6 item 1 (ratified) says "the composed `timing_jitter_s` bounds how tight Δt can go" and presents that as `ControlSpec.feasible` coupling. LINK-6b implements the timing coupling as a **response/cost law** (`η_gate`, §1.1) and the adjacent-gate condition as a **model-validity guard** (`GateLeakageGuardError`), and reserves `ControlSpec.feasible` for a genuine feasibility interval (a value the hardware cannot realise), which no 6b quantity is. No arbitrary minimum-acceptance threshold is manufactured. Because the ADR is ratified, this is recorded before dispatch as a **dated, PI-signed clarification entry in ADR-0003's status log** (body text unchanged; the entry states that §3.6 item 1's coupling sentence is illustrative motivation and that the binding mechanism is response-law + validity-guard, with `feasible` reserved) — PI decision §11-5, **confirmed**. `docs/architecture/ADR-0003-…md` therefore enters the file inventory as a **status-log-only** docs edit, appended after the 2026-07-17 RATIFIED line, with this exact text (R4 — semantic text fixed; the implementer transcribes, does not paraphrase):

> - 2026-08-18 — **PI clarification for LINK-6b (Lana):** §3.6 item 1's statement that composed `timing_jitter_s` "bounds how tight Δt can go" is illustrative motivation, not a mandate to manufacture an arbitrary hard lower bound. Under LINK-6b's centered-Gaussian timing model, timing coupling is implemented by the declared gate-acceptance response/cost law and the adjacent-gate model-validity guard (`docs/LINK_6B_PLAN.md` §1.1, §2.1). `ControlSpec.feasible` remains reserved for genuine hardware-feasibility intervals. ## 6. Declared limitations (binding language)

1. **Filter/background coupling absent:** `background_rate_hz` is the absolute post-filter incident rate by LINK-6a ownership; narrowing `filter_sigma_hz` therefore does **not** reduce it in 6b. The physically real lever "narrow the filter to cut background" needs a *background spectral density* observable and a filter-referred background owner — a follow-up (candidate LINK-6c, §13), recorded here so no benchmark in 6b claims that trade. **Enforcement is deferred (B6):** LINK-6b ships no sweep driver and `benchmark.py` is not modified; the rule "a `filter_sigma_hz` sweep must declare its Doppler-acceptance cost and may not claim a background reduction" is a **documented prohibition** in this plan only (`benchmark.py` is untouched in 6b), to be made machine-checkable by the first driver / LINK-6c.
2. **Perfect timing recovery** (zero mean arrival offset); mean-offset/synchronisation error is a future field.
3. **Residual-fraction Doppler**, not a tracker; `r` is run-level constant.
4. **Adjacent-gate leakage neglected under the guard** (§1.1).
5. **Aggregate misalignment probability**; per-basis asymmetry and geometry-coupled frame rotation deferred.
6. **Gaussian filter / Gaussian line** shapes declared; other passbands (top-hat, Lorentzian line) are future model identifiers.

## 12. The §7 rule, stated as policy (adopted 2026-08-18)

A plan may enumerate, **by exact test name and permitted change**, existing tests whose pinned facts the PR legitimately supersedes; the enumeration is made at review time (PI + Echo), before implementation, and the implementer may edit those tests only as stated. Every other existing test remains an oracle: an unlisted failure is an implementation defect. Byte-identity and parity tests are never eligible. Rejected alternatives: (a) never edit — forces design contortions and leaves tests asserting fictions; (b) implementer edits any failing test — the classic suite-rot path and incompatible with independent verification; (c) "obvious constants only" — a judgment call made by the wrong party at the wrong moment.
